# TermBeacon 现代终端极简 UI 设计

日期：2026-11-06

状态：设计已确认，待实施规划

## 1. 目标

在不改变终端、工作区、状态检测、任务历史及持久化行为的前提下，将 TermBeacon 优化为“工具框架安静、终端内容醒目、状态反馈明确”的现代终端工作台。

采用石墨黑、冷灰与克制的青蓝配色。终端直接铺满工作区剩余空间，移除外层卡片、留白、网格和光晕。浅色主题沿用相同的信息层级，不另行设计交互。

## 2. 范围

### 包含

- 重做应用配色、字体、间距、圆角、边界、阴影和焦点样式。
- 优化侧栏品牌区、工作区导航、终端列表和底部工具区的视觉层级。
- 压缩并整理工作区顶栏，强化标题，弱化路径和辅助操作。
- 让 xterm.js 终端铺满顶栏以下的全部工作区。
- 同步深色、浅色 xterm 主题，保持终端与外壳视觉一致。
- 保留任务历史、设置、更新和 Host 异常等现有界面，并统一视觉语言。
- 保留键盘焦点、状态文字和减少动态效果支持。

### 不包含

- 不修改 PTY、Agent Registry、状态机、Hook、IPC 或持久化逻辑。
- 不改变终端和工作区的创建、删除、切换、重命名及快捷键行为。
- 不引入命令面板、标签页系统、新导航结构或新功能。
- 不引入 UI 框架、图标库或新的运行时依赖。
- 不调整 Electron 窗口及发布配置。

## 3. 视觉语言

### 3.1 配色

深色主题以接近石墨黑的背景为主，侧栏和工作区使用明度接近的表面色，通过细分隔线而不是阴影划分区域。正文使用柔和冷白，辅助信息使用冷灰，青蓝只用于当前项、交互焦点和运行状态。

浅色主题使用中性浅灰应用背景与白色工作区，保持相同层级和状态语义，不直接反转深色颜色。

状态颜色继续承担现有语义：工作中为蓝色，已完成未查看为绿色，就绪为低饱和灰绿色，等待输入为琥珀色，异常为红色，已停止为灰色。颜色之外始终保留现有状态文字；异常和等待状态应具有明确但不过度闪烁的反馈。

### 3.2 字体与排版

界面使用现有系统无衬线字体栈。标题保持适中字重，避免 oversized 品牌标题和大面积粗体。路径、快捷键及终端相关内容使用系统等宽字体栈。通过字号、字重和颜色区分信息，不依赖大量容器。

统一小尺寸控件的高度、内边距和图标线宽。主要文本与控件边界需保持清晰对比，辅助文本不得因追求极简而难以辨认。

### 3.3 形状与动效

控件使用小而一致的圆角。浮层可以保留轻量阴影以建立层级，但普通列表项和终端区域不使用厚卡片、浮雕或多层阴影。

列表切换只使用短促的背景与边框过渡，取消悬浮位移。状态呼吸和脉冲保持克制，并在 `prefers-reduced-motion: reduce` 下停用非必要动画。

## 4. 布局与组件

### 4.1 侧栏

品牌区保持 TermBeacon 与副标题，缩小装饰性光晕，新建终端按钮与底部工具按钮采用一致的简洁风格。侧栏不再使用渐变背景。

工作区导航保留原有位置和全部行为，但减弱胶囊感。当前工作区通过浅底色与清晰文字体现，不再叠加多层高亮。新增工作区只保留一个图标按钮，与同一行的标签对齐。

终端列表使用紧凑、平整的条目。当前终端使用左侧细线、浅底色和较高文字对比共同标识，移除悬浮上移、厚重投影和渐变。标题为第一信息层级，Agent 与状态为第二层级，最近输出或 cwd 为第三层级；长文本继续单行省略。

删除操作仍在悬浮或焦点相关状态出现，避免覆盖标题和状态。工作区标签的 × 默认隐藏，鼠标移入标签或键盘聚焦后才显现，并占用固定宽度以避免出现时导致文字位移。重命名输入沿用现有提交、取消和焦点行为。

底部设置与主题切换保持原位，使用一致的图标按钮。设置浮层保留现有主题、默认 Shell 与快捷键内容，仅统一排版和边界。Host 异常提示继续使用明确的错误色与可操作的重启按钮。

### 4.2 工作区顶栏

顶栏采用紧凑单行布局，与侧栏品牌区形成稳定对齐。左侧显示可重命名的终端标题及其 cwd；路径使用等宽字体、省略显示和点击选择目录的既有行为。

右侧保留任务历史与按需出现的重启终端按钮。辅助按钮默认低强调，悬浮、焦点和展开时再增强反馈。标题和操作在窄窗口下不得相互覆盖，路径优先收缩。

### 4.3 终端画布

xterm.js 从顶栏下方开始铺满工作区全部剩余宽度和高度。移除外层卡片、内边距、圆角、阴影、网格与光晕，仅保留顶栏与终端之间的细分隔线。

终端容器的布局边界保持明确，`FitAddon` 继续依据实际容器尺寸调整行列。不得因 CSS 改动产生双滚动条、遮挡、不可见焦点或 resize 循环。

深色和浅色 xterm 背景分别与应用工作区背景一致。前景、光标和选择区域保持足够对比；ANSI 与全屏 TUI 内容由 xterm.js 正常呈现，不通过滤镜或全局透明度改变终端文字。

### 4.4 浮层与系统反馈

任务历史保留右侧浮层形式，使用平整表面、细边框和轻量阴影。列表沿用状态灯、任务标题、状态、时间和错误信息，统一为新的排版尺度。

更新横幅和进度提示继续位于顶栏下方、终端上方，出现时占用自身布局高度，不遮挡终端内容。设置、任务历史、更新和 Host 异常状态均同时适配深浅主题。

## 5. 实现边界

主要修改 `src/renderer/styles.css`，必要时对 `src/renderer/App.tsx` 做最小结构调整，并更新其中 `terminalThemes` 的深色、浅色背景、前景和光标颜色。现有事件处理、状态更新、终端实例 Map、IPC 调用和持久化字段保持不变。

优先复用现有 CSS 变量和组件类名。只有在现有类名无法表达必要布局时才调整 JSX，不进行组件体系重构。继续使用内联 SVG 图标，不增加依赖。

## 6. 可访问性与交互约束

- 所有可点击控件保留可见的键盘焦点样式。
- 状态不能只靠颜色表达，继续显示状态文字和已有 Tooltip。
- 删除、重命名、目录选择和任务历史行为保持与当前版本一致。
- 悬浮才出现的操作不能成为键盘用户无法访问的唯一入口。
- 支持 `prefers-reduced-motion`，关闭装饰性脉冲和过渡。
- 浅色主题不能只在应用外壳切换颜色，xterm 也必须同步切换。
- 保留现有窗口尺寸、侧栏宽度及终端适配逻辑。

## 7. 验证与完成标准

### 自动验证

- `npm run build` 成功，无 TypeScript 或 Vite 构建错误。
- `npm test` 全部通过，确认非 UI 逻辑未受影响。

### 界面验收

- 深色与浅色主题下，应用外壳和 xterm 均无突兀色块或低对比文字。
- 终端从顶栏下方铺满剩余工作区，无卡片外框、网格、光晕和多余留白。
- 新建、切换、关闭和重命名终端行为与当前版本一致。
- 工作区创建、切换、重命名和删除行为不变。
- 当前、工作中、完成未查看、等待输入、异常和停止状态可以明确区分。
- 调整窗口和侧栏宽度后，终端正确 fit，无内容截断或异常滚动条。
- 任务历史、设置、更新提示和 Host 异常提示显示正常，不遮挡关键操作。
- 键盘焦点清晰，重命名输入不会被终端焦点抢占。
- 开启减少动态效果后，装饰性动画停用。
- Windows 下分别检查常用窗口尺寸、窄窗口和多终端长列表。

完成标准是视觉上显著减少装饰和层级噪音，终端成为主要视觉区域，同时所有既有操作、状态语义和核心逻辑保持不回归。
