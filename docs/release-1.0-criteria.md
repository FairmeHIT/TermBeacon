# TermBeacon 1.0 发布门槛

更新：2026-11-10。

本文定义 `1.0.0` 的可发布范围和验收条件。`0.1.x` 可以作为公开社区版本发布，但必须明确支持范围、已知限制和未签名安装包风险；版本号只有在 `1.0.0` 的硬性条件满足后才提升。

## 1.0 范围

首个正式版只承诺 **Windows 10/11 x64**。macOS 和 Linux 的构建配置可以继续维护，但在完成原生环境验收前不列入 1.0 支持矩阵。

| 能力 | 1.0 承诺 |
| --- | --- |
| 本地终端、工作区、持久化和会话恢复 | 支持 |
| Windows x64 安装、升级、回滚和卸载 | 支持 |
| Claude Code、OpenCode 2、Pi | 支持状态接入；需完成真实任务验收 |
| Codex | 支持启动、恢复和终端使用；状态检测仍标注为推断能力 |
| 通用 Shell | 支持终端使用；状态提醒按保守启发式处理 |
| macOS/Linux 原生发布 | 不属于首个 1.0 范围 |

“支持”表示安装、启动、核心终端操作和错误恢复达到本文门槛，不表示所有 CLI 的事件格式永久兼容。CLI 版本变化需要通过兼容性测试或发布说明明确处理。

## 发布硬门槛

### 状态准确性

- Claude Code、OpenCode 2 和 Pi 各完成一套经过脱敏的真实任务验收，覆盖 `Working`、`Completed`、`Waiting for input`、`Error`、重试和长输出。
- 每个正式支持的 CLI 至少保留 10 个真实任务样本，其中至少包含一次重连或 UI 重启后的状态恢复。
- 不得存在已知的 P0/P1 状态问题：误报完成、漏报等待输入、旧事件覆盖新任务、任务完成后永久停留在 Working。
- 自动化测试、真实 CLI fixture 和窗口端到端验收结果必须能够追溯到具体 CLI 版本。

重连 fixture 必须包含窗口断开和重新连接的成对记录（`kind: "reconnect"`, `source: "window"`, `phase: "detached"` 与 `phase: "attached"`），仅在元数据中填写 `scenario: reconnect` 或只记录 PTY host 重连不计入发布证据。

本地可用 `npm run acceptance:cli -- --json --out artifacts/cli-acceptance-report.json` 生成只读进度报告。该命令只读取 CLI 版本、接入配置和已提交的 fixtures，不安装插件，也不会调用模型任务；只有 `meta.evidence` 标记为 `real` 的 fixture 才计入真实任务数量，`synthetic` fixture 只证明检测器状态覆盖。

### 安装和升级

- 在至少 3 台干净 Windows x64 机器上完成首次安装、启动、卸载和重新安装。
- 从上一稳定版本升级到候选版本，再执行一次回滚或重新安装；用户配置、凭据和工作区数据保持可用。
- 安装包是否完成 Authenticode 签名不是社区发布硬门槛；未签名时，发布说明必须明确 SmartScreen 风险、支持范围和 SHA-512 校验值。若未来接入要求签名的分发渠道，再把签名作为该渠道的单独门槛。
- 更新检查失败、下载失败、校验失败和代理断连都能给出可理解的错误，并且不会破坏当前版本。

### 稳定性和回归

- `npm test`、`npm run build`、`npm run doctor` 和 `npm run verify:dist` 全部通过。
- 真实 ConPTY 大输出、断开重连、回放、终端删除、后台服务重启流程通过验收。
- `0.9.0-rc.1` 至少经过一个完整试用周期，没有未解决的 P0/P1 问题。
- 候选版本连续两个构建没有引入新的核心工作流回归。

## 不阻塞 1.0 的事项

- 新 CLI 的接入、额外主题或设置项。
- macOS/Linux 原生安装包，除非它们被重新纳入支持范围。
- Codex 原生生命周期事件；在 Codex 仍使用推断时，必须保持 README 和发行说明中的限制描述。

## 发布证据

每次候选版本应在 `artifacts/` 保存以下证据，文件名带版本号：

- 自动化测试和构建日志。
- Windows 安装、升级、回滚、卸载验收记录。
- 每个正式支持 CLI 的版本、fixture 和真实任务结果。
- 安装包、blockmap、`latest.yml` 的哈希和远端下载校验结果。
- 未解决问题清单，以及明确标记为 P0/P1/P2/P3 的处理状态。

达到以上条件后，README 可以把社区版本表述收口为正式 `1.0.0`，并把本文件链接到发布说明中。未满足这些条件时，继续发布 `0.1.x` 社区版本，不应使用 `1.0.0` 名义。
